# スマホ承認型 AI 収益パイプライン — 戦略プレイブック

対象読者: 通勤中にスマホしか触れない。受託・スキル習得・ポイ活・せどりはやらない。
Claude に生産を全部やらせて、自分は承認だけしたい。

---

## 0. 先に期待値の話をする

参照された X / TikTok の投稿は、この実行環境のネットワーク制限で開けなかった（`x.com` /
`vt.tiktok.com` は egress ブロック）。中身を見ずに一般論を語るのは本来よくないが、
「AI 自動化で稼ぐ」系の発信は構造が共通しているので、先に注意点だけ書いておく。

**あの手の発信の主収益は、多くの場合「その方法を売ること」そのもの。**

- 自動化が本当に月数十万円を生むなら、方法を公開する動機がない（真似されて自分の取り分が減る）
- それでも公開する = 「方法を売るほうが儲かる」が答えになっているケースが多い
- 提示される数字は「累計」「他収入との合算」「グロス（経費・API 代・広告費前）」が混ざりやすい

なので真似すべきは **表に出ている手法** ではなく、**その人が実際にやっていること**
＝「コンテンツで人を集めて、何かを売る」。この生産工程だけを Claude に丸投げするのが、
本プレイブックの設計方針。

**先に結論**: 完全放置の不労所得は作れない。作れるのは
**「AI が 100% 生産して、人間は 1 日 3〜5 分だけ承認する」** 形。
規約違反・法務リスク・品質崩壊は最後の 1 段（承認）でしか止められないので、そこは残す。

## 1. この設計が満たす条件

| 要求 | 実現方法 |
|---|---|
| 通勤中にスマホだけ | 実行は GitHub Actions（クラウド）。スマホは承認ボタン専用 |
| PC を開かない | 承認は GitHub モバイルアプリの Issue コメント（`/approve <id>`） |
| Claude で自動化 | ネタ選定・台本・記事・CTA 文面はすべて Claude API が生成 |
| ポイ活/せどり/受託でない | ストック型（コンテンツ資産＋アフィリエイト＋自前デジタル商品） |
| スキル習得が前提でない | 学習コストは初期セットアップの 1〜2 時間だけ |

ランニングコスト: **月 500〜2,000 円程度**（Claude API 代が主。GitHub Actions は公開リポジトリなら無料枠内）。

## 2. 収益化の壁 — 実数（2026年8月時点）

ここを誤ると設計を全部間違える。**プラットフォーム収益は入口ではなく出口。**

| 経路 | 到達条件 | 単価 | 最初の 1 円まで |
|---|---|---|---|
| **アフィリエイト** | **条件なし（審査のみ）** | 1 件 数百〜1 万円超 | **数日〜数週** |
| **自前デジタル商品**（note / Tips / BASE） | **条件なし** | 500〜3,000 円/本 | 数週 |
| TikTok Creator Rewards | 1万フォロワー **かつ** 直近30日10万再生。動画は **1分以上** 必須（スライドショー・Duet・Stitch は対象外） | RPM 約 $0.4〜1.2（金融/ビジネス系は上振れ） | 3〜6ヶ月 |
| YouTube Shorts | 1,000 登録 **かつ** 90日で1,000万 Shorts 再生（**2027/2/1 から2,000万に引き上げ**） | 約 $0.03〜0.10 / 1,000再生 | 6ヶ月〜 |
| X 収益分配 | X Premium 課金（$8/月〜）**かつ** 500フォロワー **かつ** 3ヶ月で500万インプ（**Premium ユーザーからの表示のみ計上**） | 非公開。$30 から出金 | 3〜6ヶ月 |

出典は末尾。読み取れること:

1. **ショート動画の広告収益だけを狙う設計は、半年間タダ働きになる。**
2. **閾値ゼロで金になるのはアフィリエイトと自前商品だけ。** ここを主収益に置く。
3. だから動画・ポストは「収益源」ではなく **集客装置**。収益はプロフィール経由の
   リンクと自前商品で回収する。プラットフォーム収益は後から乗るボーナス扱い。

## 3. ニッチ選定 — 「炎上」から「お金・税金・制度」へ変える

このリポジトリは元々「炎上」を収集対象にしていた。**収益設計としては最悪の選択**なので変更した。

**炎上ネタを捨てる理由**

- TikTok / YouTube はハラスメント・誤情報を収益化対象外にする。TikTok Creator Rewards は
  コミュニティガイドライン違反歴があると **失格**。育てた資産が一発で無価値になる
- 特定の個人・企業を扱うため、名誉毀損・侮辱・プライバシー侵害の民事/刑事リスクを個人で負う
- 炎上文脈に金を出す広告主・アフィリ案件が存在しない（= 集客できても換金経路がない）

**「お金・税金・社会保険・給付金」に寄せる理由**

- 金融・ビジネス系は RPM が高い（同じ再生数でも単価が上）
- **高単価アフィリエイトが揃っている**: 会計/確定申告ソフト、証券口座、ふるさと納税、
  保険相談、税理士紹介。1 件あたりの単価が数千円〜のレンジ
- **ネタが自動供給される**: 制度改正・申請締切・年次イベント（確定申告、年末調整、
  ふるさと納税の駆け込み）。Claude が最も得意な「複雑な制度を短く言い換える」領域
- 個人を名指ししないので法務リスクが構造的に低い
- 季節性が読めるので、繁忙期（1〜3月・11〜12月）に合わせて仕込める

カテゴリは 4 本（`config.yaml` の `collection.queries`）:
`tax`（税金・確定申告・インボイス） / `subsidy`（補助金・給付金） /
`social_insurance`（年金・社会保険・扶養） / `household`（節約・ふるさと納税・NISA）

> 炎上向けのコードは削っていない。`config.yaml` にクエリを足せば復活するが、
> 上の理由から既定では無効にしている。

## 4. アーキテクチャ

```
              ┌──────────── GitHub Actions (cron 毎朝 6:00 JST) ────────────┐
              │                                                             │
  X API ──▶ 収集 ──▶ スコアリング ──▶ 安全性チェック ──▶ Claude API        │
              │                                              │              │
              │              ┌───────────────────────────────┴────────┐     │
              │              ▼                                        ▼     │
              │        縦型ショート動画                        アフィリ記事  │
              │        (TTS + スライド)                        (note/ブログ) │
              │              └───────────────┬────────────────────┘          │
              │                              ▼                              │
              │                   CTA / アフィリリンク注入                   │
              │                   (+ PR表記を自動付与)                       │
              │                              ▼                              │
              │                  ★ 承認 Issue を自動作成 ★                  │
              └──────────────────────────────┬──────────────────────────────┘
                                             │
                        ┌────────────────────▼────────────────────┐
                        │  📱 通勤中のあなた（3〜5分）            │
                        │  GitHub モバイルアプリで Issue を開く    │
                        │  `/approve tax-123`  or  `/reject ...`  │
                        └────────────────────┬────────────────────┘
                                             ▼
              ┌──────────── GitHub Actions (コメントで起動) ────────────┐
              │   TikTok / 記事下書き へ投稿  →  収益ログに記録         │
              └────────────────────────────┬───────────────────────────┘
                                           ▼
                            週次レポート Issue（毎週月曜）
                            投稿数 / 承認率 / 収益 / 次の打ち手
```

**要点**: あなたの持ち場は矢印 1 本（`/approve`）だけ。それ以外は全部クラウドで回る。

## 5. 90日プラン

### Phase 1 — Day 1〜14: 仕込み（PC が必要なのはここだけ、合計 1〜2 時間）

1. このリポジトリを自分のアカウントに置く
2. GitHub Secrets に `ANTHROPIC_API_KEY` を入れる（**これだけで動く。他は後回しで良い**）
3. アフィリエイト登録（A8.net / もしもアフィリエイト / バリューコマース あたり）。
   承認されたら `AFF_*` Secrets に貼る
4. リンク集約先（プロフィール用の 1 ページ）を作り `AFF_HUB_URL` に入れる
5. TikTok / X / note のアカウントを作る。**投稿は自動化せず、まず手動投稿で反応を見る**

この 2 週間の目的は収益ではなく **「承認するに値する原稿が出てくるか」の検証**。
出てこないなら `config.yaml` のプロンプト方針を直す。ここを飛ばすと後が全部無駄になる。

### Phase 2 — Day 15〜45: 量を出す

- 1 日 2〜3 本を承認 → 投稿。**アフィリ記事を先に積む**（動画より先に金になる）
- 記事は「制度の解説 → よくある詰まりどころ → 解決手段（＝アフィリ）」の形に固定
- 動画は TikTok の要件に合わせて **1分以上** で作る（`config.yaml` の `video.min_duration_sec`）
- ここで **最初の数百〜数千円** が出る想定。出なければ 3 のニッチ選定か CTA を見直す

### Phase 3 — Day 46〜90: 自前商品を載せる

- 積んだ記事から Claude に「まとめ商品」を作らせる（確定申告チェックリスト、
  インボイス対応の手順書など）。note / Tips / BASE で 500〜1,500 円
- 記事と動画から商品へ導線を貼る。ここで単価が跳ねる（アフィリ 1 件 ≒ 商品 1 本）
- 90 日目でプラットフォーム収益の条件に届いていれば申請。届いていなくても収益は出ている状態

## 6. 現実的な収益シミュレーション

甘い数字を書く意味がないので、素直に置く。前提: 1 日 2 本承認、週 5 日稼働。

| 時期 | 想定収益/月 | 内訳 |
|---|---|---|
| 1ヶ月目 | **0 円** | 資産ゼロ。API 代でマイナス 500〜2,000 円 |
| 2ヶ月目 | 0〜1,000 円 | アフィリが単発で発生し始める |
| 3ヶ月目 | 2,000〜8,000 円 | 記事が検索/回遊で拾われ始める |
| 6ヶ月目 | 1〜5万円 | アフィリ + 自前商品。上振れ時にプラットフォーム収益が乗る |
| 12ヶ月目 | 3〜15万円 | 確定申告シーズン（1〜3月）に季節ピークが来る |

**上振れ条件**: 確定申告・年末調整シーズンに刺さるネタを外さないこと。
**下振れ条件**: ニッチを分散させること（雑多なアカウントは伸びない）。

「月 50 万を自動で」は、この構造では出ない。出るとしたら
「自動化のやり方を売る」側に回ったときで、それは別のビジネス。

## 7. やらないこと（地雷リスト）

| やらない | 理由 |
|---|---|
| 完全自動投稿（承認なし） | TikTok の未審査アプリは `SELF_ONLY` しか投稿できない。無審査全自動は規約・法務リスクの塊 |
| 税務・投資の断定アドバイス | 税理士法・金融商品取引法。「一般的な制度の説明」に留め、出典と免責を必ず付ける |
| アフィリリンクの無表記 | 2023年10月からのステマ規制（景品表示法）。**PR 表記は自動付与している**（`monetization.disclosure`） |
| スクレイピング | X の規約違反。収集は API 経由のみ |
| 同じ動画を複数プラットフォームに透かし付きで転載 | TikTok は透かし付き転載を収益対象外にする。書き出しは各プラットフォーム個別に |
| AI 生成の非開示（Kindle 等） | KDP など開示が要求される場を使うなら申告する |
| 個人名を出す | `src/processing/safety.py` が既定でブロックしている。外さない |

---

## 8. なぜ「アフィリエイト・ファースト」なのか（設計の要）

もう一度だけ強調する。ここが本プレイブックで唯一「発想を変える」ところ。

普通の人は **動画 → 再生数 → 広告収益** を狙って、半年タダ働きして辞める。
この設計は **動画 → プロフィール → 記事 → アフィリ/商品** で、
**フォロワー 0 人でも 1 件成約すれば数千円**が入る。

だから `src/monetize/affiliate.py` が CTA を全成果物に強制注入し、
承認 Issue には「この投稿の換金経路は何か」が必ず表示される。
換金経路のないコンテンツは、この設計では作らない。
