# AliExpress → BASE 無在庫出品ツール 実現可能性の判定

作成: 2026-08-24 / 依頼: 「アリエクの商品を BASE で無在庫出品、1個あたり利益500円、自動出品」

**このドキュメントは実装前の可否判定です。** 事実 / 診断 / 数字の根拠 / 整合性チェック / 判定 の順で書きます
（`docs/OPERATIONS.md` §9 の形式に合わせる）。この機能は既存 scout システムとは別系統で、
凍結対象（100点配点・scale_gate 等）には一切触りません。置き場所は `src/dropship/` を想定。

## 1. 事実（一次情報で確認できたこと）

### 1.1 BASE 側

| 項目 | 確認できた内容 |

| 登録上限 | **API 経由でも 1日 1,000 商品まで**（API 利用の有無に関わらず同じ上限） |

### 1.2 AliExpress 側

| 項目 | 確認できた内容 |
|---|---|
| 公式 API | AliExpress Open Platform（Affiliate API / DS API）。OAuth2.0、app_key + app_secret |

| 発注 API | DS API による一括発注は実在するが、**DSers など whitelist されたパートナーが優遇**されている領域。個人アプリで発注まで通る保証は現時点で確認できていない |
| スクレイピング | ToS 違反 + Cloudflare/構造変更で壊れる。**採用しない** |

### 1.3 日本の法規制

- **特商法**: 引渡時期（注文後どのくらいで発送するか）の具体的な明記が必須。総額表示。
- **景表法**: 誇大・虚偽表示の禁止。**AliExpress の商品説明の直訳は誇大表現を含みやすい**。
- **関税・輸入消費税**: 国際送料込みの合計が **16,666円超**で関税課税。内国消費税・地方消費税は別途。
  無在庫で顧客宛に直送すると「輸入者は誰か」が曖昧になる（名義上の輸入者問題）。
- **個別法の地雷**: PSE（電気用品・モバイルバッテリーは PSE なし販売禁止）、技適（無線機能）、
  薬機法（化粧品・サプリ・医療機器）、食品衛生法、商標法・関税法（模倣品は輸入差止＋損害賠償）。
  **リチウムイオン電池内蔵品は輸送規制もあり、無在庫の対象にしない。**

## 2. 診断

### 2.1 技術的には可能。ただし「丸ごと自動転載」は不可能

`items/add` があるので**出品の自動化そのものは素直に作れる**。1日1,000件の上限も個人規模では効かない。
詰まるのは技術ではなく次の2点で、どちらも自動化の形を変える。

1. **他店の商品画像・説明文の無許可利用は BASE の明文禁止行為。**
   AliExpress のページを取得してそのまま流し込む実装＝規約違反の自動化になる。
   Affiliate/DS API 経由で利用許諾のあるアセットに限定するか、説明文は自前生成する必要がある。
2. **「商品が手元にない状態での販売」はガイドラインで原則禁止。**
   違法ではないがプラットフォームの裁量でショップ非公開にされうる。**アカウント停止＝事業ごと消える**ので、
   ここは「大量出品で薄く広く」と最も相性が悪い。出品数を絞り、発送遅延を出さない運用が前提になる。

### 2.2 1個500円利益は数式で確定する（実現可能）

スタンダードプラン（6.6% + 40円/注文）、仕入れ原価 C（AliExpress 商品代 + 国際送料）とすると

```
利益 = 販売価格 P × (1 - 0.066) - 40 - C
必要な P = (C + 540) / 0.934
```

| 仕入れ原価 C | 500円利益に必要な販売価格 P | 販売価格に対する利益率 |
|---:|---:|---:|
| 300円 | 899円 | 55.6% |
| 500円 | 1,114円 | 44.9% |
| 800円 | 1,435円 | 34.8% |
| 1,000円 | 1,649円 | 30.3% |
| 1,500円 | 2,185円 | 22.9% |
| 2,000円 | 2,720円 | 18.4% |

- **原価 1,000円までなら、日本の相場から浮かない価格で 500円利益が取れる。** 上限はこのあたり。
- 振込手数料は月1回・2万円以上でまとめれば 250円/回（40件/月なら 6円/件）。
  **2万円未満で申請すると 750円取られる**ので、月商が小さいうちは振込頻度を絞る。
- **為替**: 原価は USD/CNY 建て。円安に振れると 500円が溶ける。**マージンは固定額ではなく「500円 + 為替バッファ」**で持つ。
- **関税**: 販売価格を 16,666円未満に収めれば課税ラインを跨がない。500円利益の商材はここに収まる。

### 2.3 トラブル1件が何件分の利益を消すか

全額返金＋仕入れ回収不能を1件あたり損失 ≈ C + 40円 とすると、原価1,000円なら

```
損益分岐のトラブル率 f: 500 × (1 - f) = 1,040 × f  →  f ≈ 32%
```

**3件に1件までは金銭的には耐える。** つまり数字上のボトルネックは返金ではなく
**遅延クレームと低評価による集客の死**、そして BASE の規約判断。
AliExpress からの標準配送は 2〜4週間かかるので、特商法の引渡時期表記を正直に書けるかがそのまま生命線になる。

## 3. 整合性チェック

- **「無在庫は違法」ではない**（違法なのは模倣品・無許可商材・虚偽表示）。混同しない。
- **「規約に明文禁止がない」＝「やっていい」ではない**。ガイドライン違反での非公開措置は起こりうる。
- **500円利益が成立する = 事業が成立する、ではない。** 月2万円の利益に 40件、月10万円に 200件の受注が必要。
  ボトルネックは出品自動化ではなく**集客**で、そこは自動化では解けない。
- **発注の自動化を可否判定の前提に置かない**（DS API で個人アプリが発注まで通る確証がない）。
  出品と受注取得だけでも運用は回る。

## 4. 判定

**結論: 作れる。ただし「AliExpress の商品ページを大量に自動転載する出品ツール」としては作らない。**

作る形はこうなる。

| 工程 | 自動化 | 理由 |
|---|---|---|
| 候補抽出（AliExpress 公式 API） | 全自動 | 公式 API の範囲内 |
| 禁止商材フィルタ（PSE / 技適 / 薬機法 / 電池 / ブランド） | 全自動・**強制** | 1件の違反で事業ごと終わる |
| 価格計算（500円利益 + 為替バッファ + 端数調整） | 全自動 | 手数料モデルが確定値なので決定的に計算できる |
| 商品名・説明文 | **自前生成**（転載しない） | BASE の明文禁止行為を踏まない |
| 画像 | 許諾のあるアセットに限定 / なければ出品対象から外す | 同上 |
| BASE への出品 | **DRY_RUN 既定 + 人間の承認で公開** | ガイドライン違反の一括事故を物理的に起こせなくする |
| 受注取得（`/1/orders`）→ 発注リスト生成 | 全自動 | |
| AliExpress への発注 | **人間**（将来 DS API が通れば自動化） | 個人アプリで発注 API が通る確証がない |
| 追跡番号の取り込み → 発送通知 | 半自動 | |

この既定値（`DRY_RUN=true` / 公開は人間が押す）は、このリポジトリが既に採っている
「承認ゲートは自動化しない」と同じ設計で、理由も同じ（法務リスクの最後の1段を人間が持つ）。

### 段階（各段階が単体で価値を出す順）

- **Phase 0 — API キー不要。すぐ着手できる。**
  価格計算エンジン + 禁止商材フィルタ + 候補の CSV/JSON 出力。サンプルデータで検証可能。
  「原価いくらの商材なら 500円利益で日本の相場に収まるか」がこの段階で数字として出る。
- **Phase 1** — AliExpress 公式 API 接続（要: アプリ審査通過）
- **Phase 2** — BASE `items/add` 出品（DRY_RUN 既定、人間承認で公開）
- **Phase 3** — 受注取得 → 発注リスト → 追跡番号 → 発送通知

### オーナー側でしか進められないこと

1. BASE ショップ開設 + 特商法表記（**氏名は公開必須**。住所・電話は非公開設定を使う）
2. BASE Developers でアプリ申請（検索API は不要 / 権限は商品・注文の読み書き）
3. AliExpress Open Platform でアプリ申請（身分証の提出を求められる場合あり）
4. Secrets 登録 — **値はチャットに貼らない。必要なのは Secret 名だけ**:
   `BASE_CLIENT_ID` / `BASE_CLIENT_SECRET` / `BASE_REFRESH_TOKEN` /
   `ALIEXPRESS_APP_KEY` / `ALIEXPRESS_APP_SECRET`

### 未確認のまま残っている点（実装前に潰す）

- グロースプランで注文あたり 40円がかかるか（スタンダードは 6.6% + 40円で確定）
- `items/add` の画像パラメータの受け渡し方式（URL 指定可か、アップロードのみか）
- DS API の発注が個人アプリで通るか
- BASE の「手元にない商品の販売」原則禁止の例外の正確な線引き

`help.thebase.in` / `docs.thebase.in` / `openservice.aliexpress.com` はこの実行環境の
egress プロキシで直接取得できず、検索結果経由で確認した。**上の4点は一次情報での再確認が必要。**

## 5. 追記: 目標「1アカウント 月5万円」から逆算した利益単価（2026-08-24）

オーナーの目標が「**1アカウントで月5万円**」と確定したので、利益単価を逆算し直した。
**結論から言うと、1個500円は目標設定として不利。1,200〜1,800円/個を狙うべき。**

### 5.1 利益単価と必要件数

```
必要件数 = 50,000円 / 1件あたり利益
```

| 利益/個 | 必要件数/月 | 必要件数/日 |
|---:|---:|---:|
| **500円** | **100件** | 3.33件 |
| 800円 | 63件 | 2.10件 |
| 1,000円 | 50件 | 1.67件 |
| 1,200円 | 42件 | 1.40件 |
| **1,500円** | **34件** | 1.13件 |
| 2,000円 | 25件 | 0.83件 |
| 3,000円 | 17件 | 0.57件 |

### 5.2 なぜ500円が不利なのか

**ボトルネックは出品数ではなく受注数（＝集客）。** 出品は API で1日1,000件まで自動化できるので、
出品側はいくらでも増やせる。増やせないのは注文で、新規の BASE ショップに広告なしで
月100件を入れるのは月34件の3倍難しい。**同じ5万円を、3倍きつい戦い方で取ることになる。**

さらに§2.3のトラブル率を織り込むと差が開く（原価1,000円・トラブル率10%で期待値補正）:

| 表面利益/個 | 期待利益/個 | 必要件数/月 |
|---:|---:|---:|
| 500円 | 346円 | **145件** |
| 1,000円 | 796円 | 63件 |
| 1,400円 | 1,156円 | 44件 |
| 1,762円 | 1,482円 | 34件 |

**500円設定は、返金1件の重みが利益に対して大きすぎる。** 145件/月は個人運用の現実的な射程外。

### 5.3 では何を売るか（原価 × 値付け倍率）

中国輸入の一般的な値付け（仕入れの2.5〜3倍）で計算すると、必要な原価帯が決まる。

| 仕入原価 C | 2.5倍で売る | 利益/個 | 必要件数 | 3.0倍で売る | 利益/個 | 必要件数 |
|---:|---:|---:|---:|---:|---:|---:|
| 300円 | 750円 | 360円 | 139件 | 900円 | 501円 | 100件 |
| 500円 | 1,250円 | 628円 | 80件 | 1,500円 | 861円 | 59件 |
| **800円** | 2,000円 | 1,028円 | 49件 | **2,400円** | **1,402円** | **36件** |
| **1,000円** | 2,500円 | 1,295円 | 39件 | **3,000円** | **1,762円** | **29件** |
| 1,500円 | 3,750円 | 1,962円 | 26件 | 4,500円 | 2,663円 | 19件 |
| 2,000円 | 5,000円 | 2,630円 | 20件 | 6,000円 | 3,564円 | 15件 |

**「利益500円」を狙うと、自動的に「原価300円の激安小物を3倍で売って月100件」という一番きつい枠に入る。**
これが500円設定を退ける最大の理由。

**推奨レンジ: 仕入原価 800〜1,200円 / 販売価格 2,400〜3,600円 / 利益 1,400〜1,800円。**
月30〜36件（1日1件強）で5万円に届く。販売価格は関税ライン（16,666円）にも遠い。

### 5.4 価格計算エンジンへの反映

**利益額を 500円 固定でハードコードしない。** 次の形にパラメータ化する。

```
入力: 目標月収 / 想定受注件数 / 仕入原価 / 為替レート / トラブル率
出力: 必要な利益単価 → 必要な販売価格 → 端数調整後の売価
ガード: 利益/個 < 500円 の候補は出品しない（下限ガード）
        販売価格 > 16,666円 の候補は出品しない（関税ライン）
        値付け倍率 > 3.0 の候補は「相場から浮く」警告を付ける
```

500円は**目標ではなく下限ガード**として残す。これで「1個500円くらい」という当初の意図
（薄利で数を捌く発想）を、数字が否定した形で設計に取り込める。

### 5.5 複数アカウント運用について

「1アカウントで月5万」という言い方だったので確認した。

- **1アカウントで複数ショップは作れない。** 同一人物が複数ショップを持つこと自体は可能だが、
  **ショップごとに別アカウント**が必要。
- ただし**無在庫販売 ×複数アカウントは、BASE の裁量判断が最も厳しく出る組み合わせ**
  （§2.1 の「手元にない商品の販売は原則禁止」と重なる）。**規約上の明確な線引きは未確認。**
- **まず1ショップを月5万まで持ち上げる。** 横に増やすのはその後で、増やす前に規約を再確認する。
  1ショップが月5万に届かない状態で横展開すると、赤字と規約リスクを同時に複製することになる。

### 5.6 税務（1行だけ)

月5万円＝年60万円。**給与所得者の副業でも年20万円を超えるので確定申告が必要。**
経費（仕入・手数料・送料）の記録はツール側で自動的に残す（受注と発注のログを突き合わせられる形にする）。

### 5.7 判定の更新

§4の判定（作れる。ただし丸ごと自動転載はしない）は変わらない。**利益単価の既定値だけを変更する。**

| | 変更前 | 変更後 |
|---|---|---|
| 目標利益/個 | 500円（固定） | **1,400〜1,800円**（目標月収から逆算・可変） |
| 500円の役割 | 目標値 | **下限ガード**（これ未満は出品しない） |
| 想定仕入原価 | 〜1,000円 | **800〜1,200円** |
| 想定月間受注 | 100件 | **30〜36件** |
